# Руководство по Vaulter Collaboration

Пакеты `axiomasoft/vaulter-collaboration` и `@vaulter/vue-collaboration` реализуют протокольно-нейтральный движок совместного редактирования в реальном времени поверх `vaulter-core`, `vaulter-drive` и `vaulter-documents`.

## 1. Архитектура и протокольно-нейтральный журнал (`protocol=2`)

Laravel-бэкенд является единственным источником истины для состояния документов, прав доступа и долговременного хранения. Node.js Hub (`packages/hub`) выступает как stateless-узел реального времени: он загружает состояние комнаты из бэкенда и дописывает каждое бинарное обновление через эндпоинты `collaboration/hub/*`.

Основные таблицы `vaulter-collaboration`:
- `v_collaboration_heads` — хранит активный `protocol` (`yjs/2`, `univer-sheets/1` и др.), текущую эпоху (`epoch`), `owner_fence` и состояние compaction lease.
- `v_collaboration_updates` — append-only журнал бинарных (`bytea`) обновлений по комнате и эпохе.
- `v_collaboration_receipts` — идемпотентные квитанции применения обновлений.
- `v_collaboration_client_ids` — выделяет непересекающиеся диапазоны Yjs `clientID` (разделение по `2^31`) для исключения коллизий между серверными/AI-мутациями и браузерами.

### Бинарное хранение Yjs (`bytea`)
Все снимки и инкрементальные обновления Yjs **обязаны** храниться строго в бинарном формате `bytea` (`Y.encodeStateAsUpdate` / `Y.encodeStateAsUpdateV2`).
- **Жёсткий запрет JSON round-trip:** запрещено пересоздавать `Y.Doc` через сериализацию в JSON (например, ProseMirror JSON) и повторный импорт в новый `Y.Doc`. JSON round-trip уничтожает CRDT-надгробия, векторные часы и историю слияний, приводя к тихой порче данных и расхождению клиентов.

## 2. Room Capability JWT

Клиенты не подключаются к Hub с обычными сессионными cookie или долгоживущими API-токенами. Браузер запрашивает у Laravel короткоживущий **Room Capability JWT**:
- **Клеймы:** `sub` (актор), `tenant_id`, `document_id`, `room`, `epoch`, `role` (`editor` | `viewer`), `exp` (короткий TTL, обычно 2–5 минут), `jti`.
- **Ротация ключей:** поддерживается через заголовок `kid` и окно двойной проверки (см. `packages/collaboration/docs/key-rotation.md`).
- **Область действия:** токен жёстко привязан к тройке `(tenant_id, document_id, epoch)`. Использование токена для другой комнаты или после смены эпохи отклоняется.

## 3. Epoch Fencing (`4409` / `4412`) и `owner_fence`

При внеполосной замене состояния документа (например, восстановлении ревизии или импорте файла) Laravel инкрементирует `epoch` комнаты и выдаёт новый `owner_fence`.
- **Код закрытия WebSocket `4409` (`epoch_mismatch`):** Hub немедленно закрывает все активные соединения устаревшей эпохи с кодом `4409`. `@vaulter/vue-collaboration` перехватывает `4409`, сбрасывает устаревший локальный `Y.Doc`, запрашивает новый Room Capability JWT для актуальной эпохи и чисто переинициализирует состояние.
- **Код закрытия WebSocket `4412` (`strict_precondition_failed`):** сигнализирует о нарушении предусловий строгого профиля (например, расхождении fencing-токена).

## 4. Compaction Lease

Чтобы предотвратить неограниченный рост `v_collaboration_updates`, Hub периодически уплотняет журнал обновлений в единый бинарный снимок:
1. Воркер уплотнения получает ограниченный по времени **compaction lease** у Laravel (в PostgreSQL проверка истечения аренды выполняется через `clock_timestamp()`, а не замороженный `now()`).
2. Воркер склеивает обновления до отметки sequence и загружает компактный бинарный снимок с токеном аренды.
3. При падении воркера аренда истекает автоматически, и другой воркер (либо офлайн-команда `vaulter-collaboration-hub compact --pending`) завершает уплотнение без потери данных.

## 5. Отзыв прав (Permission Revocation)

При понижении роли (`editor` → `viewer`) или отзыве доступа к документу:
1. Laravel фиксирует отзыв прав и уведомляет control-plane Hub.
2. Hub немедленно разрывает WebSocket-сессии затронутого актора (либо переводит в read-only), не дожидаясь истечения `exp` JWT.
3. Любой последующий повтор запроса или обновление токена перепроверяет актуальные ACL и завершается fail-closed с `403 Forbidden`.

## 6. Строгий профиль `3.5` и ограничение глубины `UndoManager`

Для высоконадёжных инсталляций (совместное редактирование людей и AI в строгом профиле `3.5`):
- **Запрет Redis для данных документов:** `@hocuspocus/extension-redis` не допускается для хранения/передачи данных обновлений в строгом режиме — вся долговременность идёт через PostgreSQL-журнал (`protocol=2`).
- **Запрет `DirectConnection.transact`:** прямые мутации выполняются только через fenced-API журнала.
- **Гигиена мьютекса:** `Y.encodeStateAsUpdateV2` выносится из мьютекса записи комнаты на клон документа (потолок строгого профиля: <= 15–20 одновременных авторов на комнату).
- **Правила `UndoManager`:**
  - **На сервере:** `Y.UndoManager` **строго запрещён** на серверном `Y.Doc` (баг Yjs `#833`).
  - **На клиенте (`@vaulter/vue-collaboration`):** обязательно ограничивать глубину стека `UndoManager` (например, `maxStackSize: 100` и ограниченный `captureTimeout`), чтобы длительные сессии в браузере не раздували память.
